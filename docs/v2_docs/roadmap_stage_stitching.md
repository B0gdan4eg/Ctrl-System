## Предпосылка

Некоторые фильтры не влезают по габаритам в поле зрения камеры (FOV) целиком.
Для их полной инспекции нужно:
1. Двигать деталь под камерой моторизованным столом (**Standa 107103**, 2 линейных
   транслятора в конфигурации **XY**, контроллер **8SMC4-USB-B9-2**, 2-осевой,
   разъёмы AXIS1/AXIS2 + JOYSTICK + SYNCH IN/OUT).
2. Снять серию кадров по сетке позиций.
3. Сшить их в одно изображение с точной геометрией (для детекции дефектов и
   расчёта размеров в мм по ГОСТ 11141-84 — искажение геометрии на стыках
   недопустимо).
4. Всё — **полностью автоматически**: оператор задаёт габариты/зону, дальше
   программа сама строит сетку, двигает стол, снимает и сшивает.

Управление камерой уже реализовано (`ui/widgets/camera_widget.py`,
`core/cameras/`). Управления столом в проекте нет вообще (проверено — ни
одного упоминания ximc/motor/stage в исходниках).

## Задача 14 — Автоматическое сканирование (grid-scan)

**Новый файл:** `workers/scan_worker.py` (QThread) — координирует
стол → камера → сохранение серии кадров с метаданными позиции.

**Алгоритм:**
1. Оператор указывает габариты фильтра (мм) или прямоугольную зону сканирования.
2. `core/stage/scan_planner.py` → `build_scan_grid(width_mm, height_mm, fov_mm, overlap_pct=15..20)`
   — считает сетку позиций (row, col, x_mm, y_mm) с перекрытием
   15–20% (компенсация люфта стола и краевых артефактов U-Net-инференса
   на границе тайла).
3. Цикл по сетке: `move_to(x, y)` → `wait_for_stop()` → пауза на
   демпфирование вибрации → `camera.take_snapshot()` → сохранить
   `(frame, x_mm, y_mm)`.
4. Прогресс — сигнал `scan_progress(current, total)` в StatsPanel.
5. По завершении — передача всей серии в модуль сшивки (Задача 15).

**FOV камеры** считается из разрешения сенсора и `PIXEL_SIZE_MM` — **зависит
от Задачи 16** (точная калибровка), иначе сетка будет посчитана с ошибкой,
которая накопится на большом фильтре.

## Задача 15 — Алгоритм сшивки кадров

Т.к. Standa-столы — шаговые с известной точностью позиционирования,
сшивка **по координатам стола (детерминированная)**, а не
feature-matching/ORB-панорама — надёжнее на однородных поверхностях
фильтров, где не за что зацепиться feature-детектору.

**Новый модуль:** `core/stitching.py`
- `stitch_frames(frames: list[(np.ndarray, x_mm, y_mm)], pixel_size_mm) -> np.ndarray`
  1. Холст в пикселях = габариты сканирования / `pixel_size_mm`.
  2. Каждый кадр кладётся на холст по расчётному пиксельному офсету
     (позиция стола → пиксели через калибровку).
  3. Блендинг швов в зоне перекрытия — **переиспользовать** cosine-window
     подход из `stitch_tile_probs()` (`core/image_processing.py`) —
     тот же принцип, что уже работает для тайлов модели.
  4. **Опциональное уточнение (2-й этап, если чистого позиционирования
     недостаточно):** субпиксельная коррекция сдвига в зоне перекрытия
     через `cv2.phaseCorrelate` — компенсирует люфт привода без
     feature-matching.

**Дефекты на стыках:**
- Детекцию (U-Net + tiled inference) запускать на **уже сшитом**
  изображении зоны, а не на отдельных кадрах — иначе дефект на границе
  между двумя позициями стола будет обрезан пополам или задвоен.
- Существующий pipeline (`prepare_zone_tiles`/`stitch_tile_probs` +
  `refine_defect_mask`) уже рассчитан на большие ROI — сшитое изображение
  просто становится входом в тот же пайплайн.

  (например по индикатору/эталонной мире) с расчётным.

## Рекомендуемая последовательность

1. **№13** — драйвер + ручное управление столом из UI (без автоматики) —
   даёт немедленную пользу (юстировка, позиционирование фильтров, которые
   не влезают в текущую механику) и площадку для тестов сшивки.
2. **№16** — калибровка (px→мм, шаг стола→мм) — без неё сетка/сшивка будут
   на глазок.
3. **№14+15** — автосканирование и сшивка — самая объёмная часть,
   зависит от 13 и 16.
4. **№17** — попутные улучшения, без жёсткой привязки к остальному.
