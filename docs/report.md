# Отчёт о состоянии разработки системы автоматического контроля дефектов «Ctrl-System»

**Дата:** 30.03.2026
**Версия ПО:** 1.1 (в разработке)

---

## 1. Общее описание системы

Ctrl-System — десктопное приложение для автоматического обнаружения дефектов на оптических фильтрах методом контроля на просвет. Система использует нейросетевую модель U-Net для сегментации дефектов на изображениях, получаемых с промышленной камеры JAI RM-4200GE (разрешение 2048x2048, размер пикселя 7.4 мкм).

**Технический стек:** Python 3.x, PyTorch (U-Net), OpenCV, PySide6 (Qt).

**Архитектура модели U-Net:**
- Вход: RGB-изображение 512x512
- Encoder: 4 уровня (64 → 128 → 256 → 512 фильтров)
- Bottleneck: 1024 фильтра
- Decoder: 4 уровня с skip-connections
- Выход: бинарная маска дефектов

## 2. Результаты тестирования на реальных образцах

### 2.1. Статус детектируемых типов дефектов

| Тип дефекта | Статус | Комментарий |
|-------------|--------|-------------|
| Расклейки | ✅ Детектируются | Обнаруживаются стабильно |
| Проколы (тёмные) | ⚠️ Частично | Нестабильно — зависит от точности выделения зоны |
| Проколы (светлые пятна) | ❌ Не детектируются | Не реализована обработка светлых аномалий на маске |
| Царапины | ❌ Не детектируются | Ограничение метода просвета — вне текущего объёма задачи |

### 2.2. Выявленные проблемы при тестировании

**Основная проблема:** Неточное определение границ зон фильтра влечёт за собой каскад погрешностей:

1. В зону попадает часть тёмной маски (оправы фильтра)
2. Это смещает контрастность и яркостные характеристики зоны
3. Нормализация работает некорректно из-за искажённого распределения интенсивностей
4. Модель получает на вход изображение с неправильным контрастом
5. Точность детекции дефектов снижается

## 3. Задачи на доработку

### 3.1. [ВЫСОКИЙ] Повышение точности детекции зон

**Проблема:** Алгоритм детекции зон на основе CLAHE + пороговой обработки даёт неточные границы — в выделяемую зону попадают фрагменты тёмной маски (оправы). Это нарушает контраст зоны, что ухудшает работу нормализации и нейросети.

**Следствия неточной зоны:**
- Погрешность в определении габаритов зоны (пересчёт пиксель → мм)
- Искажение контраста при нормализации → снижение качества детекции дефектов
- Возможные ложные срабатывания/пропуски на границах зон

**Направления доработки:**
1. Улучшить алгоритм выделения контура зоны — точнее отделять светлую зону фильтра от тёмной маски
2. Рассмотреть применение морфологических операций для «зачистки» контура
3. Ввести валидацию зоны по яркостному профилю (отсечение тёмных пикселей по краям ROI)
4. Добавить коррекцию ROI — обрезать зону до «чистой» внутренней области без захвата маски

---

### 3.2. [ВЫСОКИЙ] Детекция светлых пятен (проколы)

**Проблема:** Текущая модель обучена на детекцию тёмных дефектов (расклейки). Проколы, проявляющиеся как **светлые пятна** на маске, моделью не обрабатываются — ни нейросетью, ни алгоритмически.

**Задача:** Реализовать детекцию светлых аномалий. Возможные подходы:
1. **Алгоритмический метод** — после нормализации зоны искать области с аномально высокой яркостью (превышение порога относительно среднего по зоне). Не требует переобучения модели.
2. **Расширение обучающей выборки** — добавить размеченные примеры проколов (светлые пятна) в датасет и дообучить модель на двухклассовую сегментацию (тёмные дефекты + светлые дефекты).
3. **Комбинированный подход** — алгоритмическое детектирование как быстрый baseline + нейросетевое уточнение.

**Ожидаемый результат:** Проколы отображаются в результирующей маске и учитываются в статистике и вердикте.

---

### 3.3. [СРЕДНИЙ] Повышение точности модели через обучение на полной базе данных

**Текущее состояние:** Модель обучена на ~1/3 от всей доступной выборки.

**Задача:** Провести серию экспериментов с обучением:

| Эксперимент | Описание | Ожидаемый эффект |
|-------------|----------|-----------------|
| Полная выборка | Обучить на 100% размеченных данных | Уменьшение числа пропусков и ложных срабатываний |
| Размер входа 256×256 | Уменьшить входной тайл | Ускорение обучения и инференса, возможное снижение качества |
| Размер входа 1024×1024 | Увеличить входной тайл | Лучшее сохранение пространственных деталей, выше нагрузка |
| Другая архитектура | ResNet-backbone вместо стандартного U-Net encoder | Более глубокие признаки, возможен прирост точности |
| Аугментации | Добавить агрессивные яркостные/контрастные аугментации | Лучшая устойчивость к вариациям освещения |

**Критерий оценки:** IoU (Intersection over Union) на валидационной выборке + ручная проверка на реальных образцах.

---

### 3.4. [СРЕДНИЙ] Исправление погрешности при масштабировании маски

**Проблема:** ROI зоны произвольного размера масштабируется в квадрат 512×512 без сохранения пропорций → при обратном масштабировании маски происходит непропорциональное растяжение → погрешность формы и площади дефектов.

**Решение:** Использовать letterbox-масштабирование (padding до квадрата с сохранением пропорций) и корректный обратный пересчёт координат маски.

---

### 3.5. [НИЗКИЙ] Доработка пользовательского интерфейса

- Убрать отладочные элементы, не нужные в рабочем режиме
- Увеличить область отображения изображения
- Добавить формирование отчёта о найденных дефектах (тип, размер, количество, вердикт годен/не годен)

## 5. Выводы

Система Ctrl-System работоспособна на реальных оптических фильтрах. Расклейки детектируются стабильно. Определены три ключевых направления доработки версии 1.1:

1. **Точность зон** — улучшить алгоритм выделения границ зон, исключив попадание тёмной маски в ROI. Это напрямую повлияет на точность габаритов и качество детекции дефектов.

2. **Проколы (светлые пятна)** — реализовать детекцию аномально светлых областей, которые текущей моделью не обрабатываются.

3. **Качество модели** — провести обучение на полной базе данных с экспериментами по размеру входа и архитектуре.

Царапины остаются вне текущего объёма работ — их выявление требует иного метода освещения (косое/отражённое).
