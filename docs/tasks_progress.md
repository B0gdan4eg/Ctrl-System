### Задача 8 — оптимизация инференса (точность + скорость)

Пайплайн полностью переработан.

**Tiled inference** (`prepare_zone_tiles`, `stitch_tile_probs` в `core/image_processing.py`):
- ROI после histogram normalization режется на тайлы 256×256 (sliding window, overlap 64 px = 25%)
- На каждую зону ДОПОЛНИТЕЛЬНО — один летербокс 256×256 (для крупных дефектов «целиком»)
- Косинусное окно для weighted blending на швах

**Multi-contrast fusion** в `workers/processing_worker.py`:
- Для каждой зоны делаются **два варианта** histogram normalization: `std_range=2.0` и `std_range=3.0`
- Каждый вариант проходит sliding + letterbox → 4 probs map'а на зону
- Объединение через `np.maximum.reduce` (любой режим увидел → пиксель помечен)
- На типичной картинке (5 зон 230×1932): **110 forward'ов 256×256** в двух батч-проходах

**Edge-aware refinement** в `core/defect_detection.py`:
- `refine_defect_mask()`: guided filter (R=4, eps=0.005) → hysteresis (thr_low / thr_high=0.5 / 0.7) → морфология
- `_intensity_shrink()`: интенсивностная подгонка границ — для каждой компоненты строится кольцо-фон (адаптивная ширина), пиксели с яркостью близкой к фону отсекаются (k_sigma=2.5 или 1.5 для крупных)
- Safety checks: при шумном фоне (bg_std>22) shrink не применяется

**Производительность:**
- GPU (RTX 5050): **~2 сек/кадр**
- CPU (стенд без GPU, после оптимизаций): **~14 сек/кадр** (без оптимизаций было 20)
- Auto-detect: `torch.device('cuda' if torch.cuda.is_available() else 'cpu')`

## Задача 3 — Исправление масштабирования ✅

**Срок:** 27.03.2026
**Выполнено:** 02.03.2026

### Проблема
При подаче ROI зоны в модель U-Net применялся непропорциональный resize (stretch):
- ROI произвольного размера, например 800×600, растягивался в 512×512
- Коэффициент масштабирования по X и Y был разным (0.64 vs 0.853)
- Выходная маска 512×512 растягивалась обратно в 800×600
- Результат: искажение формы дефектов, неверный расчёт площади

### Решение — Letterbox resize
Заменён непропорциональный stretch на letterbox (вписывание с padding):
1. ROI вписывается в 512×512 с сохранением пропорций (один коэффициент `scale = min(512/W, 512/H)`)
2. Незаполненные края заполняются чёрным padding'ом
3. Модель обрабатывает 512×512 с реальным изображением в центре
4. После детекции padding вырезается, маска возвращается к исходному размеру через тот же `scale`

## Задача 7 — Фикс зависания QFileDialog ✅

**Выполнено:** 05.05.2026

### Проблема
При нажатии "Загрузить изображение" приложение виснет.

### Причина
В `main.py:14` вызывался `CoInitializeEx(None, 0x0)` с комментарием
`# COINIT_APARTMENTTHREADED`, но `0x0` это `COINIT_MULTITHREADED` (MTA).
Главный поток оказывался в MTA, а нативный Windows-диалог Open File
требует STA на главном потоке — отсюда зависание.

### Решение
Заменено на `0x2` (`COINIT_APARTMENTTHREADED`).

### Проблема с зонами — диагноз

Пользователь сообщил о двух симптомах после letterbox-изменения:

**Симптом 1: На некоторых изображениях зоны вообще не определяются**
- `find_top_zones` сам НЕ менялся (git diff подтверждает)
- Вероятно — pre-existing проблема с конкретными изображениями (низкий контраст, нестандартное освещение)
- НЕ связано с letterbox (zone finding происходит ДО любой предобработки для модели)

**Симптом 2: "Пересвет" / артефакты в зонах где они определились**
- Вероятная причина: letterbox padding с чёрными (0) полями
- Модель **не обучалась** на изображениях с чёрными border'ами
- Граница "реальный пиксель → 0" вызывает ложные активации модели по краям ROI
- `restore_mask_letterbox` корректно вырезает padding-зону, но артефакты на краях реального контента остаются

### Что нужно сделать завтра

**Фикс 1 (СРОЧНО) — заменить чёрный padding на отражённый:**
В `core/image_processing.py`, функция `resize_with_letterbox`:
```python
# Было:
canvas = np.zeros((target_h, target_w), dtype=image.dtype)
canvas[pad_y:pad_y + new_h, pad_x:pad_x + new_w] = resized

# Надо:
canvas = cv2.copyMakeBorder(
    resized,
    pad_y, target_h - new_h - pad_y,   # top, bottom
    pad_x, target_w - new_w - pad_x,   # left, right
    cv2.BORDER_REFLECT_101              # зеркальное отражение краёв
)
```
Это сохраняет геометрию (пропорции) И не вводит артефакты на границе модели.

**Фикс 2 — разобраться с зонами на "сложных" изображениях:**
- Нужны конкретные изображения где зоны не находятся
- Возможно нужно переключить worker на `find_top_zones_improved` вместо `find_top_zones`
  (improved версия уже есть в `core/zone_detection.py`, но worker её не использует)
